UK State Pension Explorer: living launch audit

Updated: 8 October 2026, UK time. Recommendation: hold launch until the seven P1 items below are closed or, where appropriate, explicitly accepted with evidence. No P0 defect was established. This audit is not a certificate of financial accuracy or WCAG conformance.

Target: authenticated Netlify preview. Source: private GitHub repository, current main ZIP obtained through the owner's authenticated browser; GitHub showed ccdf841 on 6 October. The archive has no Git history. Deployed commit identity was not independently mapped to this archive. No repository code, account settings or deployment was changed.

Decision summary

The core is strong: static pages, separate arithmetic libraries, entitlement/illustration distinctions, documented rounding, source registers, benefit caveats, honest preview/review labels and production build guards. All 31 current tests passed, and the build/content checks passed: 19 registered pages, 126 figures, 158 claims and 104 sources. Many September audit defects are repaired and are not repeated as current findings.

Launch risk centres on assurance: current policy evidence has changed; a populated budget control can unexpectedly reinterpret money; accessibility remains partly assessed; some high-impact spreadsheet values lack fresh cell-level verification; build dependencies need security triage; and public release configuration has not been exercised on the final domain.

P0: critical. P1: resolve before launch. P2: material improvement, usually after P1 closure. P3: enhancement. Unperformed checks are unverified, not passes or failures. All findings below are open. Suggested owners are roles, not named assignments.

Findings register

A01 — P1: reconcile reform claims with current DWP evidence

Evidence: social-care page says the announcement does not specify payment components and marks lowest-income effects unanswered. Current src/reform-social-care.njk retains those questions. DWP analysis updated 6 October identifies basic/new pension coverage, CPI treatment of other pre-2016 components and conditional poverty analysis.

Reproduce: compare “What rule would replace…” and “What happens to people on the lowest incomes?” with the source's method/impacts sections. An old check date cannot establish the version of a mutable source.

Impact: readers can infer evidence is absent when it exists. A sentence restricted to the original announcement can be valid, but the wider synthesis needs later evidence. The costs page already includes DWP method and cash/real estimates: that older omission is fixed.

Fix/closure: update reform overview, costs, social-care questions and claim/source records together. Distinguish announcement, model and legislation; discuss the poverty result conditionally, not as a guarantee. Preserve genuine unresolved Pension Credit/funding questions. Record source versions and human review. Owner: policy/editorial reviewer.

A02 — P1: explicitly show the conflicting care timetable

Evidence: social-care explainer describes summer 2027 while also presenting earlier phases. Terms updated 1 October retain first-phase 2026 and second-phase by 2028 wording; the 29 September announcement refers to summer 2027.

Reproduce: compare timeline/delivery questions with both official documents.

Fix/closure: present each date with its document/version and scope; explicitly flag the conflict rather than inventing a harmonised timetable. Review the amended remit too. Transparent uncertainty is acceptable closure if official clarification is unavailable. Owner: editor.

A03 — P1: populated budget period changes reinterpret money

Evidence: live reproduced on budget explorer. src/assets/js/tools/budget.js:44 explicitly records this as previously declined behaviour; that decision does not remove the user risk.

Reproduce: choose week; click “Fill in the full new State Pension (£241.30 a week)”; change period to calendar month. Once updated, the field still contains £241.30 and annual income changes from £12,547.60 to £2,895.60. Equivalent monthly income is approximately £1,045.63. No immediate guard explains what happens to existing values.

Impact: a reader expecting a unit conversion can produce a materially misleading budget. Arithmetic follows the selected period; the defect is interaction design.

Fix/closure: convert populated amounts with disclosed rounding, or offer a clear choice to convert/reinterpret/clear. Include helper/preset amounts, tax and all four periods in interaction regression checks. Preserve the already-fixed helper that respects an existing monthly period and other income. Owner: developer/UX reviewer.

A04 — P1: complete minimum human accessibility assurance

Evidence: statement, src/_data/a11y.json and docs/accessibility-assessment.md honestly say incomplete. Recorded automated checks are dated 5 October. Human keyboard, VoiceOver/Safari, NVDA/Windows, actual zoom/touch and non-Chrome rounds are incomplete. New stale-result state was not in the recorded automated scan.

Reproduce: read the not-done list; use a calculator with keyboard/screen reader through incomplete input, recovery, household/scenario changes and table navigation.

Fix/closure: record human keyboard, 200%/400% zoom, Safari/VoiceOver and real-phone key journeys before launch; scan stale states. Obtain NVDA/Windows evidence before a full AA claim. Disclose remaining gaps and provide an accessible feedback route. An environment date is not testing evidence. Owner: accessibility tester/publisher. This is an assurance gap, not a demonstrated criterion failure.

A05 — P1: verify unresolved source cells independently

Evidence: fresh value scan did not find 12 unquoted figures in text: Pension Credit non-recipients 820,000; overseas pension recipients 1,102,000; pension expenditure £136.6bn/£154.2bn; pensioner benefits £164.9bn; National Insurance Fund pension expenditure £136.9bn; MIS £273.57 excluding rent/£136.93 rent; wealth quartiles £76,000/£591,300; pension wealth £130,500/£31,000. These are verification exceptions, not proven errors. Passage checking accepts 21 cached browser confirmations.

Reproduce: inspect reports/values.json and reports/passages.json after the scripts; locate the exact workbook/PDF table through src/_data/sources.json. Numeric appearance alone does not verify denominator, period, units or geography.

Fix/closure: record release/file, sheet/table, row/column, units, geography, estimate/forecast/outturn status and derivation for every exception. Recheck cached confirmations against current versions or clearly retain their older evidence date. Reconcile different accounting bases rather than treating superficially different totals as errors. Owner: data reviewer.

A06 — P1: triage vulnerable build/test dependencies

Evidence: current lock audit reports 19 affected packages: 15 high, 4 moderate, 0 critical. Direct dependencies are development-only Eleventy 3.1.6, pa11y-ci 4.1.1 and http-server 14.1.1. The tree includes basic-ftp, braces, extract-zip and sprintf-js advisories. Totals include transitively affected packages, not 19 independent vulnerabilities.

Reproduce: install the locked tree in isolation; run npm audit --json; inspect reachability through build inputs, browser downloads and local tooling. References: basic-ftp, braces, extract-zip, sprintf-js.

Fix/closure: supported upgrades or justified narrow overrides; rerun tests/build and accessibility tooling. Document reachability/acceptance of any remaining advisory. Avoid blind force fixes: npm's suggested Eleventy downgrade is unsuitable. Static pages do not deliver these Node packages to readers, but build/CI exposure matters. No public-site exploit established. Owner: developer/build owner.

A07 — P1: prove release configuration and correction access

Evidence: preview auth/noindex are intentional. Fresh negative check confirms production config refuses missing domain/title, owner, reviewer/date, accessibility date, correction route and crawler policy. netlify.toml still selects preview in production context; intended domain is https://ukstatepensionexplorer.org. Private-repository issue links cannot be assumed publicly usable.

Reproduce: inspect docs/launch-dependencies.md, src/_data/site.js and Netlify config; load production settings without required values and observe rejection.

Fix/closure: domain/TLS, accurate actual review metadata, correctly scoped preview credentials, anonymously usable correction/accessibility contact, local production fixture and final public smoke check. Verify 200/404/redirects, canonicals, robots/sitemap, public noindex/auth/banner removal, error-page noindex, headers and analytics. Record deployed commit/rollback. Owner: publisher. This audit did not deploy or weaken protection.

A08 — P2: clarify automatic sharing of custom monetary values

Evidence/repro: entering synthetic £987.65 in comparison automatically writes start=987.65 to the query after a delay. Privacy page discloses host/history implications; the issue is design, not a false claim of undisclosed storage.

Fix/closure: explicit “Copy scenario link” action preferred; alternatively omit custom money from automatic queries or consider a fragment. Place a warning beside the control and inspect production analytics requests. Owner: developer/privacy reviewer.

A09 — P2: retain fallback on partial script failure

Evidence: src/_includes/base.njk:35 loads js-class.js; .js .no-js-only hides fallback before individual modules initialise. A subsequent module/import failure can leave a non-working form/default result. Source-confirmed risk, not observed live outage.

Reproduce: controlled local preview blocks the tool module but allows the global class script.

Fix/closure: enable each tool only after successful initialisation; retain explanatory fallback until then, with a failure notice and regression check. Owner: developer.

A10 — P2: narrow the DWP caveat

Evidence: claim dwp-2030-caution says not to work out a saving in a single year; DWP publishes in-year endpoints and cautions against deriving further individual-year point estimates.

Fix/closure: prohibit unsupported interpolation/extrapolation of a precise annual profile, rather than implying the published endpoints cannot be cited. Retain nominal £15bn/£50bn versus 2025/26-price £11bn/£30bn distinctions and expenditure savings versus care funding. Owner: editor; fold into A01.

A11 — P2: improve narrow-screen charts/tables

Evidence: 720-unit chart view box/small labels and internal wide-content scrolling; existing UX docs acknowledge small type and unclear sideways-scroll affordance. No fresh mobile WCAG failure established.

Reproduce: real narrow phone, history/comparison charts and long tables; compare cells while scrolling.

Fix/closure: visible scroll cue, prominent table alternative, larger/simpler chart labels, context-preserving headers where reliable; older-reader testing. 44px is a useful house aim, not the AA minimum of 24px with exceptions. Owner: UX/developer.

A12 — P2: clarify the hypothetical start of the 2030 rule

Evidence/repro: comparison can apply “Rule announced for April 2030” from a selected earlier year, including 2027; caveats explain the abstraction farther down.

Fix/closure: beside the first-year control say all rules are compared mechanically from the chosen start, rather than representing the announced transition. Only add a rollout scenario with defined/sourced assumptions. Owner: editor/developer.

A13 — P2: consolidate conflicting documentation status

Evidence: docs/HANDOVER.md reports 6 October live checks and steps 1/2 done but “Tracked separately” still says main beyond sign-in unchecked. It says up to PR24; GitHub main showed PR25. Launch dependencies retain step 1 without clear completion status.

Fix/closure: one dated status/evidence/commit/owner checklist, linked rather than repeated. Distinguish preview from production checks. Prefer locked npm ci guidance and directly declare tooling imported by scripts rather than depending on incidental transitive availability. Owner: maintainer.

A14 — P2: broaden meaningful interaction regressions

Evidence: 31 pure-calculation tests pass; selected live regressions pass, but A03 shows why they do not establish all financial UI behaviour.

Fix/closure: period/helper preservation, tax blank/zero, incomplete/error recovery, household/scenario changes, malformed/restored URLs, history subranges/exports, partial-load failure and focus/announcements. Exact pension-age boundary tests are needed if a personal age calculator is added; current site explains the timetable. Owner: developer.

A15 — P2: surface actionable eligibility/tax caveats

Evidence: pre-2016/contracting-out and household caveats are useful. Allowance freeze detail extends beyond the shorter tax headline; overseas voluntary NI rules changed from April 2026.

Fix/closure: surface the current freeze end date; label official forecast/NI-record/voluntary-contribution guidance near gap-filling discussion. Explain that contributions may not increase a pension and overseas rules differ. References: new pension, voluntary NI abroad, Finance Act 2026. Owner: editor.

Code, security, privacy and performance

Code: arithmetic/view/controller separation, bounded inputs, exact monetary conventions and model/reference docs are positive. Shared escaping and constrained select/query values reduce injection risk; no exploitable injection established. Browser regressions, failure paths, tooling declarations and provenance assurance remain gaps.

Security: source CSP restricts scripts/connections, framing, objects, base and form actions. Netlify defines nosniff, frame denial, referrer policy and disabled camera/microphone/geolocation. Anonymous 401 showed HSTS. Source configuration does not prove final public headers. Analytics identifier is public, not a leaked credential. Preview secrets intentionally enter build header rules; verify artifact/log access and the narrow secret-scan omission. ZIP cannot establish historic secret exposure. A06 is build-chain triage, not a proven runtime exploit.

Privacy: budget data is not intentionally put in URLs/storage; back-navigation clearing passed. Comparison/history settings are shareable queries, including custom amounts. Privacy disclosure acknowledges this. Inspect actual production beacon, host retention/access and ownership before final privacy assertions. Do not assume a consent banner requirement purely from the presence of an analytics script; examine actual behaviour and applicable rules.

Performance: static pages/self-hosted assets are favourable. Local raw/gzip estimates: CSS 23.3KB/6.6KB; source register 245KB/45KB; costs 83KB/14KB; budget 55KB/9KB; comparison 47KB/10KB. These do not establish host compression or loading speed. Source correctly revalidates non-fingerprinted assets. Measure cold/warm mobile loading, compression/cache headers, tool responsiveness and long-register navigation after blockers; no Core Web Vitals pass claimed.
